# Backend setup

This guide covers the Python side of the application: the FastAPI server, the Gmail poller, the AI pipeline, and the helper scripts.

All commands below are run from the repository root (the folder that contains `pyproject.toml`).

## 1. What the backend does

| File | Role |
| --- | --- |
| `app/config.py` | Loads `.env` and exposes `settings` (database, Gmail, model and dashboard credentials). |
| `app/db.py` | All PostgreSQL access via `psycopg` — events, tickets, messages and knowledge base. |
| `app/gmail.py` | Gmail API client: reads mail, creates the `ai-processed` / `needs-human` labels, sends replies. |
| `app/guards.py` | Simple Python rules that skip mail we must not answer (ours, bulk, auto-submitted). |
| `app/ai/` | Classifier, reply agent, schemas and deterministic issue-routing rules. |
| `app/ai/decide.py` | Combines the two models plus the Python rules into one `Decision`. |
| `app/pipeline.py` | Turns one Gmail message into an event, a ticket and (usually) a reply. |
| `app/poller.py` | Loop that calls `poll_once()` every `POLL_INTERVAL_SECONDS`. |
| `app/main.py` | FastAPI app, `/api/...` endpoints, Basic-auth gate, static dashboard mount. |
| `scripts/` | One-off helpers (OAuth token, Gmail check, knowledge-base seed). |
| `evals/` | Golden-email evaluation dataset and runner. |

The flow is: **Gmail → poller → guards → classifier → agent → Python rules → reply or escalation**. Every step is recorded in Supabase. The models propose; Python decides.

## 2. Prerequisites

- **Python 3.13 or newer** — `pyproject.toml` declares `requires-python = ">=3.13"` and `.python-version` is `3.13`.
- **uv** — the project uses `pyproject.toml` + `uv.lock`; `uv sync` is the documented install command.
- A **Supabase/PostgreSQL database** reachable by a connection string — see [supabase_setup.md](supabase_setup.md).
- **Google Cloud OAuth credentials** for the Gmail API (steps below).
- An **OpenAI API key** (the models are `openai:...`).

## 3. Install Python dependencies

```bash
uv sync
```

`uv sync` installs the runtime dependencies from `uv.lock` and, by default, the `dev` group.

Runtime dependencies (from `pyproject.toml`, versions resolved in `uv.lock`):

| Package | Purpose |
| --- | --- |
| `fastapi[standard]` | HTTP API and static file serving. Brings `uvicorn`. |
| `google-api-python-client` | Gmail API client. |

| `openai` | LLM provider used through Pydantic AI. |

`dev` group (needed only for the token helper and evals):

If you used `uv sync --no-dev`, add them back with:

```bash
uv sync --group dev
```

## 4. Configure `.env`

```bash
cp .env.example .env
```

Then fill in the values. **Never commit `.env` or `credentials.json`** — both are already in `.gitignore`.

| Variable | Required | Where it comes from |
| --- | --- | --- |
| `GOOGLE_CLIENT_ID` | yes | Google OAuth client (written automatically by the token helper). |
| `GOOGLE_CLIENT_SECRET` | yes | Google OAuth client (written automatically by the token helper). |
| `GOOGLE_REFRESH_TOKEN` | yes | Generated by `scripts/get_refresh_token.py`. |
| `DATABASE_URL` | yes | Supabase/PostgreSQL connection string, e.g. `postgresql://user:password@host:5432/postgres`. |
| `OPENAI_API_KEY` | yes | OpenAI dashboard. Used by Pydantic AI. |
| `CLASSIFIER_MODEL` | recommended | triage model; `.env.example` uses `openai:gpt-4o-mini`. |
| `AGENT_MODEL` | recommended | reply-writing model; `.env.example` uses `openai:gpt-4o`. |
| `POLL_INTERVAL_SECONDS` | no | seconds between inbox checks; code default is `60` (the example file shows `30`). |
| `DASHBOARD_USERNAME` | no | dashboard Basic-auth user; default `admin`. |
| `DASHBOARD_PASSWORD` | yes for login | dashboard Basic-auth password; **must be non-empty** or every `/api/...` call returns 401. |
| `PYDANTIC_AI_NO_BANNER` | no | `1` suppresses the Pydantic AI banner. |

Notes:

- `app/config.py` declares `google_client_id`, `google_client_secret`, `google_refresh_token` and `database_url` with no defaults, so the app will not start without them.
- `CLASSIFIER_MODEL` and `AGENT_MODEL` have code defaults (`openai/gpt-6-luna`). Set them explicitly in `.env` (as `.env.example` does) so you know which models you are paying for.

## 5. Google / Gmail credentials

The code uses an **installed-app OAuth flow** (`InstalledAppFlow.from_client_secrets_file`) and the scope `https://www.googleapis.com/auth/gmail.modify`. It needs a refresh token because the poller runs unattended.

1. In Google Cloud Console, create/select a project and enable the **Gmail API**.
2. Configure the OAuth consent screen. Add your own mailbox as a **test user** while the app is in testing.
3. Create an **OAuth client ID** of type **Desktop app**.
4. Download the client JSON and save it as `credentials.json` in the repository root (the exact path expected by `scripts/get_refresh_token.py`).
5. Make sure `.env` already exists — the helper only writes into an existing file.
6. Generate and store the token:

```bash
uv run python scripts/get_refresh_token.py
```

A browser window opens for Google login. On success the script writes `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and `GOOGLE_REFRESH_TOKEN` into `.env`.

If no refresh token is returned, revoke the app at <https://myaccount.google.com/connections> and run the script again.

On the first successful connection, `app/gmail.py` automatically creates two Gmail labels if they do not exist:

- `ai-processed` — applied to handled mail so it is never processed twice.
- `needs-human` — applied to escalated threads; while present, the bot leaves the thread to a colleague.

## 6. Prepare the database

Run the Supabase migrations and seed the knowledge base **before** starting the app — the agent reads knowledge-base rows from PostgreSQL when it answers mail.

See [supabase_setup.md](supabase_setup.md) for the schema and migration steps, then:

```bash
uv run python scripts/seed_knowledge_base.py
```

This reads every `*.md` file in `knowledge_base/` and upserts one row per `##` heading into the `knowledge_base` table. It is safe to re-run; it updates existing `(section, title)` rows instead of duplicating them.

## 7. Run the backend

Three long-running commands are used locally, one per terminal.

**Terminal 1 — FastAPI (port 8000):**

```bash
uv run uvicorn app.main:app --reload --port 8000
```

**Terminal 2 — Gmail poller:**

```bash
uv run python -m app.poller
```

It starts by connecting to Gmail, logs the mailbox address, then loops with `time.sleep(settings.poll_interval_seconds)`. Three consecutive errors cause the Gmail client to be rebuilt rather than crashing the process.

**Terminal 3 — frontend:** see [frontend_setup.md](frontend_setup.md).

Only start the poller once you are ready for it to **read and reply to real mail** in the connected mailbox.

## 8. Verify the setup

Replace `admin:your-dashboard-password` with the values from your `.env` — the file is read by the app, not exported into your shell.

```bash
curl http://localhost:8000/health
# {"status":"ok"}

curl -u admin:your-dashboard-password http://localhost:8000/api/login
# {"ok":true}

curl -u admin:your-dashboard-password http://localhost:8000/api/tickets
```

`/health` is the only unauthenticated endpoint. Everything under `/api` requires HTTP Basic auth; a missing or wrong `DASHBOARD_PASSWORD` returns 401.

API endpoints exposed by `app/main.py`:

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/health` | Liveness check, no auth. |
| `GET` | `/api/login` | Credential check used by the dashboard. |
| `GET` | `/api/events` | Last 100 processing events. |
| `GET` | `/api/tickets` | Last 100 tickets. |
| `GET` | `/api/tickets/{ticket_id}/messages` | Conversation for one ticket. |
| `GET` | `/api/knowledge-base` | All knowledge-base rows. |
| `PUT` | `/api/knowledge-base/{entry_id}` | Edit title/content of one row. |
| `POST` | `/api/poll` | Trigger one inbox poll. |

A Gmail-only smoke test is available, but be careful: **`scripts/gmail_check.py` sends a real reply** to the newest unprocessed message and labels it `ai-processed`.

```bash
uv run python scripts/gmail_check.py
```

## 9. Evaluations (optional)

```bash
uv run python -m evals.run_evals
```

`evals/golden_emails.py` holds the golden cases; `evals/run_evals.py` checks that `decide()` returns the expected `section` and `action`. This calls the configured OpenAI models and requires the knowledge base to be seeded.

## 10. Production-style run

**Option A — single Docker container:**

```bash
docker compose up --build
```

The Dockerfile builds the frontend (`node:20-alpine`), installs Python dependencies with `uv` on `python:3.13-slim`, copies the built dashboard into `dashboard/dist`, and starts `uvicorn app.main:app --host 0.0.0.0 --port 8000`. Compose maps `8000:8000`, passes `.env` via `env_file`, and health-checks `/health`.

Note: the container starts only the web process. The **poller is not started by docker-compose**; run `uv run python -m app.poller` separately (or schedule the `/api/poll` endpoint) if you want automatic inbox checks.

**Option B — local build served by FastAPI:**

```bash
cd dashboard && npm run build && cd ..
uv run uvicorn app.main:app --port 8000
```

`app/main.py` mounts `dashboard/dist` at `/` if that directory exists, so no separate static server is needed. The mount happens at import time — build the dashboard before starting uvicorn, and restart uvicorn after rebuilding.

## 11. Known issues in the current code

These are observations from reading the code, not setup steps:

- `POST /api/poll` calls `poll_once()` with no arguments, but `app/poller.py` defines `poll_once(gmail: Gmail)`. The dashboard's "Check inbox now" button therefore raises a `TypeError`; the background poller (`python -m app.poller`) passes the client correctly and works.
- `app/ai/classifier.py` lists sections such as `web-development` and `ai-powered-systems`, while `app/ai/schemas.py` and the seeded knowledge base use names such as `requiretments and support` and `services and solutions`. Expect classification mismatches until these are aligned.
- `supabase/config.toml` declares a seed path `./seed.sql`, but no such file exists. The real seeding step is `scripts/seed_knowledge_base.py` above.
